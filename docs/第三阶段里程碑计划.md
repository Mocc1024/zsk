## 一、目标与验收口径

**阶段目标**：打通「生产 → 消费 → 沉淀用户」闭环。

1. 后台内容以**前台站点 + 开放 API** 两种形式对外交付，具备基础的流量统计与 SEO 能力；
2. 建立**独立的 C 端用户体系**（注册、登录、个人中心），让用户能收藏、评论并与内容互动；
3. 通过**等级 + 积分**把用户行为沉淀为可运营资产。

### 1.1 量化口径（阶段出口以此为准）

| 指标 | 阶段前基线 | 阶段目标 | 度量方式 |
| --- | --- | --- | --- |
| 主链路贯通率（注册→登录→浏览→收藏→评论→得积分→升级） | 0%（无 C 端用户） | 100% | 手工走一遍并留截图；脚本化 curl 回归链 |
| 未登录访问受限接口返回 401 | — | 100% | 逐接口探针（参照第二阶段 11.7 权限矩阵做法） |
| 重复收藏幂等 / 取消后计数回落 | — | 100% | 同一内容连点收藏 5 次，`favorite_count` 仅 +1；取消后回落 |
| 积分流水与余额一致性 | — | 100%，且无负数 | 并发 100 次积分发放后 `SUM(流水) == 用户余额` |
| 后台发布内容前台可见延迟 | 不适用（无前台） | ≤ 60 秒 | 发布后计时轮询前台详情接口 |
| 开放 API 鉴权拦截率 | — | 100% | 无密钥 / 错签名 / 过期 timestamp 三类请求全部被拒 |
| 评论敏感词命中进待审 | — | 100% | 敏感词样本库全量命中 `status=0` |
| 前台首屏加载 | — | < 2s（本地环境） | Chrome DevTools Network，禁用缓存 |
| 移动端主流分辨率无错位 | — | 360 / 390 / 414 三档全通过 | DevTools 设备模拟逐页检查 |

### 1.2 非目标（本阶段不做）

短信验证码、第三方 OAuth 登录、积分商城与兑换、多站点、审核工作流、AI 辅助——前两项已拆出本阶段（见 ADR-006），其余属第四阶段。

**为什么把短信与第三方登录拿掉**：两者都依赖外部资质（短信服务商账号、微信开放平台应用审核），周期不可控。把它们放在关键路径上会让「注册登录」这个最前置的里程碑卡在等待上，而后续收藏、评论、积分全都依赖它。故主路径改走**账号密码 + 图形验证码**，外部依赖后置为 M3.8 增强项。

## 四、里程碑详情

### M3.0 · 准备：地基（5 人日）

**范围**

1. **数据库迁移 SQL**（3 个脚本，幂等 + 回滚，用 `php scripts/run_sql.php` 执行）
   - `database/upgrade_front_v3.sql`：14 张新表（见第七节）
   - `database/upgrade_content_seo.sql`：`zsk_content` 增加 `seo_title` / `seo_keywords` / `seo_description` / `favorite_count` / `comment_count`
   - `database/upgrade_content_search.sql`：中文全文索引 `ft_search`（M3.2 搜索落地前执行即可，见 ADR-012）
2. **权限点**：`database/upgrade_permission_p3.sql`，新增「用户管理」「互动管理」两个顶级菜单及 `user.*` / `comment.*` / `report.*` / `level.*` / `points.*` / `open.*` 权限点（清单见第六节）；为「编辑」类用户组按需授权，`rules='*'` 超管组不受影响
3. **三套鉴权**（关键地基，见 ADR-007）
   - 后台管理员：现有 `app/middleware/Auth.php`（不动）
   - C 端用户：新增 `app/middleware/UserAuth.php`，校验 `role=user` 的 JWT
   - 开放 API：新增 `app/middleware/OpenAuth.php`，AppKey + HMAC 签名
   - `app/service/Jwt.php` 扩展：payload 支持 `role` 与 `type`（access / refresh）；Refresh Token 黑名单落 Redis
4. **Redis 接入**：`config/cache.php` 新增 `redis` store；装 phpredis 并验证
5. **前台工程脚手架**：新建 `portal/`（React 18 + Vite + Antd 5 + react-router-dom 6），产物输出 `public/portal`，dev 端口 5174（避开后台 5173），代理 `/api` → `127.0.0.1:8000`
6. **敏感词与等级种子**：`zsk_sensitive_word` 基础词库（200 条量级）、`zsk_user_level` 6 级默认规则

**交付物**：2 个建表 SQL + 1 个权限 SQL、3 个中间件、`portal/` 可跑通的空白工程（含布局与路由骨架）

**验收**
- 三个 SQL 连跑 2 轮均成功且无重复数据（沿用第二阶段 10.3 口径）
- 新权限点出现在权限树，对未授权角色不可见
- 用 admin token 调 C 端接口 → 401；用 user token 调后台接口 → 401（**三套体系互不串用**）
- 开放 API 不带签名 → 拒绝
- `php -m` 可见 redis；`portal/` 与 `web/` 可同时 dev 不冲突

### M3.1 · 开放内容 API（5 人日）

**范围**

1. `zsk_open_app` 表 + 后台「开放应用」管理（AppKey / AppSecret 生成、启停用、密钥轮换、可配允许的路径与 QPS）
2. 接口：`GET /api/open/categories`、`GET /api/open/contents`、`GET /api/open/content/:id`、`GET /api/open/tags`
3. 签名协议：`appkey` + `timestamp` + `nonce` + `sign`，`sign = HMAC-SHA256(appsecret, 排序后的参数串)`；`timestamp` 偏差 ±5 分钟，`nonce` Redis 去重防重放（TTL 10 分钟）
4. 限流：令牌桶（Redis 原子计数），按 AppKey 维度，超限返回 429
5. **只返回已发布内容**（`status=1` 且 `publish_time <= now`），正文输出前二次过 `HtmlFilter`

**验收**
- 合法签名正常取数；无密钥 / 错签名 / 过期 timestamp / 重放 nonce 四类请求全部被拒
- QPS 超限稳定返回 429，不穿透到数据库
- 后台下架内容后，开放 API 立即不可见

### M3.2 · 前台站点基础（10 人日）

**接口（前台专用，免鉴权只读；与 `/api/open/*` 分离，见 ADR-011）**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/front/home` | 首页聚合：置顶 + 最新 + 热门 + 分类导航 |
| GET | `/api/front/contents` | 列表（分类 / 标签 / 分页 / 排序） |
| GET | `/api/front/content/:id` | 详情（正文二次过滤 + 计数） |
| GET | `/api/front/search` | 搜索 + 关键词高亮 |
| POST | `/api/front/stat/view` | PV/UV 上报 |

**范围**

1. 页面：首页（轮播/置顶/最新/热门）、分类页、详情页、标签页、搜索页、404
2. PV/UV 上报：`POST /api/front/stat/view`，写 `zsk_content_stat`（日粒度，`(content_id, date)` 唯一）并累加 `zsk_content.views`；UV 按「当日 IP + UA 哈希」去重
3. 搜索：MySQL 全文索引（`FULLTEXT(title, summary, content)`，需 `ngram` 分词以支持中文），关键词高亮
4. 响应式：360 / 390 / 414 三档适配，详情页字号与行高按移动端重设
5. 详情页正文二次过滤（防后台编辑引入脚本）

**验收**
- 五个页面在 PC 与三档移动端均无错位
- 详情页刷新 3 次 → `views` +3、当日 UV 仅 +1
- 搜索命中标题/摘要/正文，关键词高亮正确，XSS 样本不执行

### M3.3 · 用户注册登录与个人中心（8 人日）

**范围**

1. 注册：用户名 + 密码（强度校验）+ 协议勾选；密码 bcrypt
2. 登录：账号密码 + **图形验证码**（Captcha 服务，纯 PHP GD 生成，存 Redis，60 秒有效）；连续失败 5 次锁定 15 分钟
3. 双 Token：Access（2 小时）+ Refresh（7 天）；刷新接口；登出/封禁时 Refresh 进 Redis 黑名单
4. 个人中心：昵称、头像（复用素材库上传接口，但走用户维度鉴权）、性别、生日、简介；修改密码；注销（软删除 + 30 天冷却期）
5. 前台登录/注册页 + 全局用户态（`UserAuthContext`）

**验收**
- 注册 → 登录 → 拿 token → 访问受限接口 全通；未登录一律 401
- 密码错误 5 次后锁定，锁定期内正确密码也拒绝
- Access 过期后 Refresh 可续期；登出后旧 Refresh 立即失效
- 注销后 30 天内可恢复，超期不可登录

> 手机号 / 邮箱 / 第三方登录的**数据字段本阶段先建好**（`mobile` / `email` / `zsk_user_oauth` 表），M3.8 或第四阶段补通道，避免届时再改表。

### M3.4 · 收藏与订阅（3 人日）

**范围**：收藏 / 取消收藏（唯一索引 `(user_id, content_id)` 保证幂等）、收藏夹分组、`zsk_content.favorite_count` 冗余计数（事务内同步，异步校正脚本兜底）、「我的收藏」页、分类/标签订阅开关

**验收**：同一内容连点收藏 5 次，`favorite_count` 仅 +1；取消后回落；列表页计数与详情一致

### M3.5 · 评论互动（7 人日）

**范围**

1. 评论、楼中楼回复（`pid` / `root_id`）、点赞（`zsk_comment_like` 唯一索引）
2. 提交侧：HTML 白名单过滤（`HtmlFilter` 复用）、敏感词匹配（命中进待审）、频率限制（同用户 30 秒一条）
3. 先审后发开关（后台可切免审）；作者/管理员删除；举报（`zsk_user_report`）
4. `zsk_content.comment_count` 冗余计数

**验收**
- 楼中楼两级结构正确，删除父评论后子评论处理明确（保留并标记 or 一并隐藏，需定死）
- 敏感词样本 100% 进待审；先审后发开关切换即时生效

## 五、技术选型决策（ADR）

| 编号 | 决策 | 结论 | 理由 / 代价 |
| --- | --- | --- | --- |
| ADR-005 | 前台工程形态 | **React + Vite SPA**，独立目录 `portal/`，产物 `public/portal` | 与后台 `web/` 同栈，开发最快、零学习成本。代价：SPA 天然不利于 SEO，用「Sitemap + 热点详情页静态化 + meta 动态写入」兜底（3.5 / 3.6 本就有此规划）。若后续 SEO 成为硬指标，再单独立项切 SSR，页面组件可复用 |
| ADR-006 | 注册登录主路径 | **账号密码 + 图形验证码**先上；短信 / 邮箱 / 第三方 OAuth **后置** | 见 1.2：外部资质周期不可控，不能压在关键路径上。数据字段与 `zsk_user_oauth` 表本阶段先建好 |
| ADR-007 | 三套鉴权体系 | admin JWT / user JWT / AppKey+签名，**三套中间件完全隔离** | 与计划书 4.5「双 Token 体系」一致，并补齐开放 API 第三套。user JWT 复用 `app/service/Jwt.php`，payload 增 `role` 与 `type` |
| ADR-008 | 缓存与黑名单介质 | **Redis**（本机小皮面板） | 支持列表缓存标签失效、nonce 防重放、令牌桶限流、Token 黑名单。需为 PHP 8.3.33 **ZTS** 装 phpredis **TS 版**；若暂未装上，M3.0 – M3.2 可先回落到 File 缓存，M3.3 前必须补齐（双 Token 黑名单依赖它） |
| ADR-009 | 前台路由模式 | BrowserRouter + Nginx `try_files` 回退 | 路径干净利于 SEO 与分享；需在 `server/` 补 rewrite 配置。若部署环境不支持 rewrite，退回 HashRouter（仅改 `portal/` 一处） |
| ADR-010 | 互动计数 | 冗余字段 + 事务内同步 + 异步校正脚本 | 计划书 4.5 已定：避免列表页实时 count。校正脚本 `php think stat:correct` 每日跑，或在第四阶段纳入定时任务 |
| ADR-011 | 前台接口与开放 API 分离 | 前台 SPA 调 `/api/front/*`（免鉴权只读），第三方调 `/api/open/*`（AppKey 签名） | 计划书 9.2 只定义了 `/api/front/auth\|user\|favorite\|comment\|points\|level\|signin`，**没有前台内容读取接口**，本阶段补齐。两者不混用：混用会让前台平白承担签名复杂度，而第三方又拿不到免鉴权读接口 |
| ADR-012 | 搜索方案 | MySQL 全文索引 + `ngram` 分词，`database/upgrade_content_search.sql` | 实测 MySQL 5.7.26、`ngram_token_size = 2`，可直接用。已知限制：单字关键词不命中（最小 token 2 字）、正文含 HTML 标签会被一并索引，需在应用层二次过滤。数据量上来后再评估切 Elasticsearch |

### 后台新建用户（M3.7 增补）

新增权限点 `user.create`（111），内容运营组已获授；`POST api/user-manage` 创建 C 端用户：

### 过程中修掉的真实缺陷（都是跑起来才暴露的）

1. **`zsk_user.mobile` 唯一索引撞空串** — 建表时写成 `NOT NULL DEFAULT ''`，第二个用户注册就 `Duplicate entry ''`。改为 `DEFAULT NULL`（唯一索引允许多个 NULL）。已出 `fix_user_mobile_v3.sql`。
2. **`toArray()` 拿不到 `delete_time`** — `User` 模型把它放进 `$hidden`，导致登录时的「注销冷却期」判断永远为真，恢复与超期拦截两条逻辑都是死的。改用 `$user->getAttr()`。关键字段的判断一律不能用 `toArray()`。
3. **`zsk_category` 没有 `pid`** — 开放 API 分类接口按有父级写的，直接报未知列。分类是平级结构。
4. **`manualChunks` 对象写法不生效** — `react` 分包只有 0.03 kB，`react-dom/client` 没被匹配到。改函数形式按路径判断。
5. **授权割裂：运营能审评论，却开不了先审后发**（M3.7 交付后实测发现）— 初版授权把 `comment.config`(124) / `points.rule`(127) / `points.stat`(128) 单独留给超管，只把审核动作 `121/122/123/125/126` 给了内容运营组。结果用 `editor`（组 2）登录后，打开「评论配置 / 敏感词库 / 积分规则 / 积分统计」四个页签全部 **403**。**审核与审核所依据的规则必须由同一批人维护**，已把这三项补授给内容运营组；顺带补齐该组缺失的 `101/102/103/104/106/107/108/141`。刻意仍留给超管：`105` 重置密码、`109/110` 等级增删、`142-145` 应用增删改与密钥轮换。

> **权限改动后的生效方式**：后端 `Permission::can()` 每请求实时查库，`zsk_auth_group.rules` 改完立即生效；
> 但后台前端的权限列表存在 `localStorage`，需在页面上**刷新一次**（`AuthProvider` mount 时会重拉 `profile()`），不必重新登录。
6. **默认缓存驱动写死 `redis`，扩展缺失时后台配置接口直接 500**（M3.7 交付后实测发现）— `config/cache.php` 里 `'default' => env('CACHE_DRIVER', 'redis')`，而 `Setting::all()`、`SensitiveWordService::words()` 走的都是默认驱动。未装 redis 扩展的环境下 `think\cache\driver\Redis` 直接抛 `not support: redis`，**评论配置 / 积分规则 / 敏感词 / 验证码 / 登录限流全部不可用**。改成两层防御：① 默认驱动自动探测（扩展存在且端口连通才用 redis，否则回退 file，可用 `CACHE_DRIVER` 显式指定）；② `Setting` 与 `SensitiveWordService` 的缓存读写包 try/catch —— 缓存只是加速，不可用就直接查库，不该让读配置整个 500。

> **为什么探针没抓到**：开发机装了 redis 扩展，默认驱动一直是 redis 且工作正常，
> 全量回归 147 项全过。只有换到没装扩展的机器运行才暴露。
> 现在已补一轮「强制 `CACHE_DRIVER=file` 跑全量回归」的验证，147 项同样全过。
7. **全文索引劣化：库里有、搜索搜不到** — 跑回归时 `test_front_api` 的全文检索两项稳定失败。定位过程：插入内容后立即 `MATCH ... AGAINST` 相关度为 `0`，`OPTIMIZE TABLE zsk_content` 后变成 `17.68`；重建索引后再插入新内容能立即检索（score 5.36 / 3.17 / 2.19），说明**索引本身脏了，不是新文档入不了索引**。InnoDB 全文索引是增量 + 标记删除的，删改内容后旧分词不会立刻消失，攒多了就会出现这种情况。已加维护脚本 `scripts/refresh_search_index.php`，建议低峰定时跑（本次执行 0.43 秒）。
8. **Windows 版 Redis（3.0.504）的 `sAdd` 偶发返回 0** — UV 统计偶发少算一次（约 1/5）。加日志抓到现场：全新 key、新访客、无异常，`sAdd` 仍然返回 `0`，即服务端自身的问题（该移植版本 2016 年已停止维护）。`$added === 1` 的判断与「Redis 不可用只算 PV」的降级逻辑都是对的，没有改代码；只在探针里补发一次再判——偶发能自愈，真挂了补发也一样是 0，照样 FAIL。
9. **种子数据凭空承诺等级权益** — `seed_front_v3.sql` 原来写着「Lv2 解锁收藏夹分组、评论点赞」「Lv3 评论免审核发布」「Lv5 可申请内容推荐位」，但**代码里从来没有按等级鉴权过**：收藏、评论、点赞只看是否登录，评论是否需审核只看 `comment.audit_first` 开关与敏感词命中。文案在承诺不存在的权限，会同时误导运营（以为要配等级才开放功能）和用户（以为低等级不能用）。已全部改为中性的标识说明。

### 等级的定位：只作标记，不参与鉴权

- **收藏、评论、点赞对所有已登录用户开放**，与等级无关 —— 这是当前实现，也是后续要守住的约束
- **等级只是「成长到什么阶段」的标记**，用于头像旁 / 用户列表的展示（Lv3 中级读者）

- 早期种子数据的 `rights_desc` 曾写成权益清单，属于凭空承诺，已纠正为「新用户初始标识 / 入门成长标识 / …」

已把这条纪律写进代码注释（`FavoriteController`、`CommentController` 类注释，以及 `LevelController`、`PointController@levels`），
并在 `test_favorite_comment.php` 加了断言「当前用户是 Lv1（等级不是操作门槛）」——
同时把用户经验清零、等级强制设为 1 再跑完全部互动用例，防止哪天有人加回按等级鉴权。
10. **前台整页白屏：`frontApi.categories` 未定义** — `http://www.zsk.com/` 打开一片空白（连导航页脚都没有），但接口层全部正常：curl 打 `/`、`/assets/*.js`、`/api/front/home` 全是 200 且有数据，Vite 构建也通过。用 headless Chrome 抓控制台才看到根因：`TypeError: frontApi.categories is not a function` —— `BasicLayout` 在 `useEffect` 里调 `frontApi.categories()` 取导航分类，而 `api/index.js` 的 `frontApi` 上没有这个方法；组件抛错后整棵 React 树卸载，于是什么都没有。在 `frontApi` 补一行 `categories: () => request.get('/front/categories')` 即修复。
   **为什么层层验证都没抓到**：构建只查语法、不查方法是否存在；探针只测 API、不测渲染；curl 只看接口、不看页面。排查时也走了弯路——先怀疑 MIME、CORS、缓存，其实直接抓控制台一步到位。**以后「页面白屏 / 不渲染」类问题，第一动作就是抓浏览器控制台**，别在接口层打转。

### 本地域名部署（www.zsk.com）

| 入口 | 地址 |
| --- | --- |
| 前台 | **http://www.zsk.com/** |
| 后台 | http://www.zsk.com/admin/ |
| API | http://www.zsk.com/api/... |

**依赖**：`hosts` 里 `127.0.0.1 www.zsk.com`；小皮面板 Nginx 1.15.11 + PHP-FPM（127.0.0.1:9001）。
配置文件：`E:\phpstudy_pro\Extensions\Nginx1.15.11\conf\vhosts\www.zsk.com_80.conf`（已备份为 `.bak`）。
改完需**以管理员身份** `nginx -s reload`，普通权限会报 `OpenEvent ... Access is denied`，且失败时页面仍是旧配置，容易误判。

**站点配置要点**（`root` 保持 `E:/M/zsk/public` 不动）：

```nginx
location ^~ /api/        { try_files $uri $uri/ /index.php?s=$uri&$args; }  # API 走 ThinkPHP
location = /             { try_files /portal/index.html =404; }             # 前台站点根
location /               { try_files $uri /portal$uri /portal/index.html; } # 静态 + SPA 回退
location ~ \.php(.*)$    { fastcgi_pass 127.0.0.1:9001; ... }               # PHP 保持原样
```

即：先在 `public` 下找（`storage` 上传图、`robots.txt`），再找前台产物 `public/portal`，都没有就回退前台 `index.html`。

**为什么要 SPA 回退**：前台用 `BrowserRouter`（URL 是真实路径，便于 SEO），
`/content/123` 刷新时服务器上没有这个文件，不回退就是 404。后台是 `HashRouter`，不需要。

**踩过的坑**：

1. **不要为了「站点根看起来更干净」把 `root` 改到 `public/portal`**。
   主 `nginx.conf` 的 http 块里有全局 `error_page 403/404 /error/xxx.html`，
   站点根换成 portal 后这些文件不存在，于是 **API 的报错被替换成前台 index.html ——
   body 是 HTML、状态却是 403**，连 `add_header` 调试头都会被内部重定向冲掉，极难排查。
   保持 `root = public`，PHP 通路与原来完全一致，error 页也还在。
2. **前台 `base` 与产物目录要对应**：`base: '/'`（默认）对应部署在站点根；
   本地想直接开 `http://127.0.0.1:8000/portal/` 预览时需 `VITE_BASE_PATH=/portal/ npm run build`。
   两者不对应时症状是「HTML 200、JS 404 → 白屏」。现已按站点根部署，用默认 `base`。

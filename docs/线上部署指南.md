# 全民健身模块线上部署指南

> 适用于把本地这套系统（含全民健身模块）搬到线上服务器。
> 项目：ThinkPHP 8 + React/Vite 后台 + Nginx；后台部署路径 `/zsk-cms-7c4e/`。

## 一、线上环境要求

| 项 | 要求 |
| --- | --- |
| PHP | ≥ 8.0（本地为 8.3.33 ZTS），装 `pdo_mysql`；开放 API 需 `php_redis` |
| Web 服务器 | Nginx（需支持 rewrite） |
| 数据库 | MySQL 5.7+（本地 5.7.26） |
| Composer | 用于安装 PHP 依赖（`vendor/` 不入库） |
| Node.js | 仅构建前端用，可在本地构建后上传产物 |

## 二、上线步骤

### 1. 上传代码

把项目传到线上站点目录（例：`/www/wwwroot/zsk`），**排除**以下本地内容：

```
vendor/          # 线上重新 composer install
runtime/         # 运行时缓存/日志，线上自动生成
web/node_modules/
.git/
```

保留 `app/ config/ route/ database/ public/ web/src/ composer.json .env.example`（如有）。

### 2. 安装 PHP 依赖

```bash
cd /www/wwwroot/zsk
composer install --no-dev --optimize-autoloader
```

### 3. 配置 .env

从本地 `.env` 复制一份到线上并**按线上实际修改**：

```ini
APP_DEBUG = false                    ; 线上务必关闭，避免报错泄露路径

DB_TYPE = mysql
DB_HOST = 数据库地址
DB_NAME = 线上库名
DB_USER = 线上账号
DB_PASS = 线上密码
DB_PORT = 3306
DB_CHARSET = utf8mb4
DB_PREFIX = zsk_

JWT_SECRET = 换成一个随机的长字符串   ; 不要直接用本地这个值
JWT_TTL = 7200
SITE_URL = https://你的域名           ; sitemap 生成绝对地址需要
```

> `JWT_SECRET` 换了以后，所有已签发的令牌会失效，用户需重新登录——上线时一次性做好。

### 4. 导入数据库

**新建库的情况**，按依赖顺序导入全部 SQL：

```bash
php scripts/run_sql.php database/zsk.sql
php scripts/run_sql.php database/auth_rbac.sql
# 其余 upgrade_*.sql、seed_*.sql 按文件名/里程碑顺序执行（见 docs 各阶段里程碑）
php scripts/run_sql.php database/upgrade_fitness_v1.sql      # 全民健身建表
php scripts/run_sql.php database/upgrade_fitness_menu.sql    # 全民健身菜单权限
```

**已有线上库（只加全民健身模块）**：只执行最后两条即可，两个脚本都是幂等的，重复执行不会重复建表或插菜单。

### 5. 构建并上传前端产物

在本地（或线上装 Node 后）构建：

```bash
cd web && npm run build
```

产物输出到 `public/zsk-cms-7c4e/`，把整个目录上传到线上的 `public/zsk-cms-7c4e/`。
`base` 已固定为 `/zsk-cms-7c4e/`，无需改配置。

### 6. 配置 Nginx

站点 `root` 指向 `public`（**不要**改到 `public/zsk-cms-7c4e`，否则 error 页与 API 报错会被替换成后台 HTML）。核心规则：

```nginx
server {
    listen 80;
    server_name 你的域名;
    root /www/wwwroot/zsk/public;
    index index.php index.html;

    # 后台 API 走 ThinkPHP
    location ^~ /api/ {
        try_files $uri $uri/ /index.php?s=$uri&$args;
    }
    # 后台静态目录
    location ^~ /zsk-cms-7c4e/ {
        try_files $uri $uri/ =404;
    }
    # 上传文件
    location ^~ /storage/ {
        try_files $uri $uri/ =404;
    }
    # 前台站点（如启用）
    location = / { try_files /portal/index.html =404; }
    location / { try_files $uri /portal$uri /portal/index.html; }

    location ~ \.php(.*)$ {
        fastcgi_pass 127.0.0.1:9000;   # 按线上 PHP-FPM 实际端口
        fastcgi_index index.php;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
```

改完重载：`nginx -s reload`（Windows 需管理员权限，Linux 用 `systemctl reload nginx`）。

### 7. 目录权限

```bash
chmod -R 755 runtime public/storage
chown -R www:www runtime public/storage   # 用户按实际调整
```

确保 PHP-FPM 用户能写 `runtime/`（日志、缓存）和 `public/storage/`（上传图片/证书）。

## 三、上线后验证清单

| 检查项 | 期望 |
| --- | --- |
| `http://域名/zsk-cms-7c4e/` | 后台登录页正常显示，JS/CSS 无 404 |
| 用超管登录 | 侧边栏出现「全民健身」栏目，位于「内容管理」之上 |
| 统计管理 | 不报 500（多表聚合 SQL 在 MySQL 5.7+ 可跑） |
| 门店管理 | 能新增门店 |
| 教练/会员管理 | 能新增（会写 `zsk_user`），头像/证书上传成功 |
| 上传图片 | `public/storage` 下生成文件且可访问 |
| 权限验证 | 用非超管组登录，未勾选 `fitness.*` 时看不到该栏目 |

## 四、只上全民健身模块（线上已有系统）

不动其他功能，只加这一个模块时，按下面清单操作。

### 第 1 步：数据库（必须，2 条命令）

只需执行这两条幂等脚本，不碰任何原有表：

```bash
php scripts/run_sql.php database/upgrade_fitness_v1.sql      # 建 7 张 zsk_fitness_* 表
php scripts/run_sql.php database/upgrade_fitness_menu.sql    # 写入菜单 ID 600-699
```

### 第 2 步：后端文件（按"新增 / 修改"区别对待）

**A. 直接上传的新文件（共 6 个，线上原本没有，上传不会覆盖任何东西）：**

```
app/service/FitnessService.php
app/controller/FitnessStatController.php
app/controller/FitnessStoreController.php
app/controller/FitnessCoachController.php
app/controller/FitnessMemberController.php
app/controller/FitnessEnterpriseController.php
```

**B. 修改的共享文件（2 个，需要把新增内容合并进去，不能整文件盲覆盖）：**

- `route/app.php`：在鉴权路由组的**末尾**追加了「全民健身」路由块（`// ---- 全民健身` 到企业管理路由），紧挨在 `})->middleware(\app\middleware\Auth::class);` 之前，当前共 49 条。
- `config/auth_route.php`：在权限映射数组末尾（`// 权限菜单管理` 之前）追加了 `// ---- 全民健身` 的 49 条 `[方法, 路径, 权限点]` 映射。

> 若线上这两个文件与本地改动前完全一致，可直接用本地版本覆盖；若线上另有改动，只把上面标注的新增块粘贴进去即可。

### 第 3 步：前端（必须整体覆盖，不能只传 5 个页面文件）

Vite 构建会重新生成整个 `public/zsk-cms-7c4e/`（入口 `index.html` 会引用全部带 hash 的 JS，且改了 `App.jsx` 的路由）。**只传新增的 5 个 chunk 会导致路由注册不进去、页面打不开。**

正确做法：

```bash
cd web && npm run build
```

然后把整个 `public/zsk-cms-7c4e/` 目录上传覆盖线上同名目录（构建配置 `emptyOutDir: true`，本地产物已是完整的一套）。

### 第 4 步：清缓存、验证

- 浏览器清 localStorage（菜单缓存在 `zsk_menus`）后重新登录，或直接重新登录超管。
- 确认侧边栏「全民健身」出现且在「内容管理」之上 → 说明菜单 ID 写入成功。
- 其余验证项见第三节。

**可选**：执行 `php scripts/gen_docs.php` 同步文档（不影响运行）。

**不需要做的**：改 Nginx、改 `.env`、动 `vendor/`、动其他数据表——这些线上都已就位。

## 五、常见坑

- **后台白屏 / JS 404**：`base` 与实际部署目录不一致，或产物没传全。
- **API 报 403 且 body 是 HTML**：Nginx `root` 指错目录，导致全局 error_page 把 API 报错替换成前端页面。
- **菜单不显示**：菜单 ID 段 600–699 没写进库，或当前用户组未勾选权限点；清浏览器 localStorage 后重新登录。
- **上传失败**：`public/storage` 不可写，或 `UPLOAD_LIMITS` 限制（图片 5MB）。
- **Token 全部失效**：`.env` 的 `JWT_SECRET` 与签发时不一致，重新登录即可。
